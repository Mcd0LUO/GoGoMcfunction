# GGM 交接手册

> 给下一个会话。读完这一份应当能直接开工，不需要再翻旧对话。
> 所有数字都是**实测**的，不是估计；凡是没验证过的判断，明确标注。

## 0. 一句话

**GGM 是一门编译到 Minecraft Java 1.12.2 `.mcfunction` 的小语言。**
目标用户是数据包作者（20 人以内）。编译器是 Go，无第三方依赖。

这个项目存在的**唯一理由**：

```text
1.12.2 的选择器条件是【区间】不是相等：score_x=N 意为 x <= N。
```

手写这个错误**不会报错**，只会静默多匹配。所以编译器把这件事变成不可能写错。

### 1.1 版本号有两个，它们不是同一个

- `Version` = 编译器版本（0.6.0）
- `SpecVersion` = 语言规范版本（1.0）

编译器实现的是规范的一个**子集**。两者都印在 `ggm -version` 里。
三条测试强制这个一致性（`internal/version/version_test.go`）。

### 1.2 版本号规则

- **生成结果的含义变了** → 次版本号（0.x → 0.y），golden 必须重签
- 只是内部重构 → 补丁号
- **0.x 期间允许破坏性改动**，这正是停在 1.0 以下的意义

## 3. 铁律（1.12.2 的事实，全部有出处）

**这一节是整份文档最重要的部分。** 每一条都踩过坑，且每一条都能静默产生错误结果。

### 3.1 选择器是区间，不是相等 ★最重要

| 源码 | 发射的条件 | 含义 |
|---|---|---|
| `a < b` | `score_T=-1` | T <= -1 |
| `a <= b` | `score_T=0` | T <= 0 |
| `a > b` | `score_T_min=1` | T >= 1 |
| `a >= b` | `score_T_min=0` | T >= 0 |
| `a == b` | `score_T_min=0,score_T=0` | **两个界都要** |
| `a != b` | 两条守卫（或一条 `unless`） | 析取 |

**等号必须同时给上下界；不等号必须给两条备选。** 写错不报错，只会静默多匹配。

### 3.2 1.12.2 没有 `tag` 命令

那是 1.13 的。1.12.2 用：

```mcfunction
scoreboard players tag <选择器> add|remove|list <标签>
```

**未知命令会让整份函数文件加载失败**——同文件里其它命令一起失效。
这条极其危险：一个拼错的命令能悄悄废掉整个文件。

### 3.3 `function` 支持 `if` / `unless`

出处是游戏自己的语言文件：

```text
commands.function.usage=/function <name> [if <selector>|unless <selector>]
```

反编译的 `CommandFunction.execute` 确实比对 `"if"` / `"unless"`。
不匹配时抛 `commands.function.skipped`（`Skipped execution of function 'X'`）。

**这是单合取分支能省一条命令的原因**：一侧 `if`、另一侧 `unless`。

### 3.4 `@s` 是整个调用栈共用的一个寄存器文件

所有名字（参数 `a<N>`、局部 `l<N>`、临时 `t<N>`）
**必须在模块内唯一**，直到分配器能证明不重叠。**没有逃逸分析。**

### 3.5 1.12.2 没有的东西

| 没有 | 后果 |
|---|---|
| 动态函数名 | 不能 `function ns:` + 变量 |
| 数组 / 索引 | 「按 key 查表」只能展开成 N 条守卫 |
| 实体引用 | **没有 `@e[uuid=…]`**，无法判断「某个特定实体是否还活着」 |
| 浮点 | 计分板只有 int32；小数用千分比自己约定 |
| `nbt={…}` 选择器参数 | 1.13 才有，写了报 `Invalid selector argument` |

### 3.6 objective 名上限 16 字符

字段 objective 是 `"<类>.<字段>"` 截断而来，所以**类名前 6 字符相同的两个类会撞车**。
由 `E_FIELD_COLLISION` 报出。

### 3.7 其它

- `#` 注释**运行期零成本**（运行时跳过），但默认**关闭**，用 `-comments` 打开
- `function` 调用：1.12.2 是**入队展开**，调用者报告 0 条命令，顶层累计
- `MinecraftKey` 会**同时小写化命名空间和路径**

## 4. 架构

```text
cmd/ggm  →  driver  →  syntax  →  lower  →  optimize  →  backend/mcfunction
                ↓                    ↓
            comptime              ir + analysis
```

| 包 | 职责 | 关键点 |
|---|---|---|
| `syntax` | 词法/语法/AST | `walk.go` 提供通用 Visitor |
| `comptime` | 编译期求值 | `Eval` / `Subst` / `Range` / `Int` / `Str` |
| `ir` | 中间表示 | CFG：`Block{ID,Ops,Term}`；`logic.go` 是**补集的唯一实现** |
| `target` | **版本事实的唯一出处** | `CondAlts` / `Condition` / `SelectorArgOK` / `FitObjective` |
| `lower` | AST → IR | `lower.go` / `expr.go` / `stmt.go` / `call.go` / `predicate.go` |
| `optimize` | 优化与裁剪 | `level.go` 定义 O0–O3 |
| `analysis` | 结构不变量 | `invariants.go` |
| `backend/mcfunction` | IR → 文本 | `Validate` 是写盘前最后一道闸 |

### 4.1 两条设计原则

**1. 版本知识只有一个出处。** 任何「1.12.2 是什么样」的判断都必须落在 `internal/target`。
散在别处就会出现两份实现，然后它们会分叉（**已经分叉过一次，见 5.4**）。

**2. 补集只有一份实现。** `ir.Negate`。谁都不许自己再算一遍。

## 5. 血泪史（踩过的坑与根因）

**这一节比架构更重要。** 这些 bug 全部是**静默误编译**——不崩溃、不报错、只是结果错。

### 5.1 三个静默误编译（`luo/math`）

| 症状 | 根因 |
|---|---|
| 参数被嵌套调用覆盖 | 只看了直接调用者，没做**传递闭包** |
| 局部变量互相串味 | 每个函数的局部**独立编号**，而不是模块内唯一 |
| 临时变量被合并错 | 着色用了**单向**干扰边 + 只看一个块的活跃性 |

修法：传递闭包求 clobber、模块级编号池、对称 `addEdge`、精确 `analysis.LiveOut`。

> 教训：**`@s` 是共享寄存器文件。任何「这个函数里只有我自己」的假设都是错的。**

### 5.2 `tag_add` 叠了三个 bug

1. 发的是 1.13 的裸 `tag` 命令（1.12.2 没有，且会让**整份文件**加载失败）
2. 参数索引取错（取了 1 而不是 0）
3. 目标硬编码成 `@s`，把调用者传的选择器整个丢掉
4. 参数缺失时 `strArg` 静默返回 `""`

### 5.3 补集有过三份实现，其中两份已经分叉

分叉的那两份会发出 `score_x_min=2147483648`（超出 int32，非法）。
**修法：统一到 `ir.Negate`，其它地方一律不许自己算。**

### 5.4 `!=` 结构上无法表达

`target.CondFor` 只能返回**一个** Cond，而 `d != 0` 的真值是**两段区间**。
所以它解析通过、一用就报 `unsupported comparison`。**这个运算符此前根本不存在。**

根因还是分叉：它同时返回「真值」和「补集」，而**补集从来没人用**（一律由 `ir.Negate` 推导）。
修法：换成 `CondAlts`，返回**分支列表**，删掉那个没人用的补集返回值。

> **它藏了这么久，是因为没有任何测试覆盖比较运算符本身。** 现在有了 6 × N 条。

### 5.5 `class` 有七个缺陷，每个遮住下一个

| 症状 | 后果 |
|---|---|
| `@tick fn` 解析失败 | 规范自己的例子编译不了 |
| 字段名落成新局部变量 | 初始值设进一个再也不会被读的 objective |
| 兄弟方法调到 `<ns>/方法名` | 调用不存在的函数；而那个方法又因无人调用被删——**两个错误互相掩护** |
| 没有东西调用 ` @tick` 方法 | 类永远不跑 |
| 类选择器解析后从未使用 | 扇出不到实例 |
| 方法没进签名表 | 元数不检查、ABI 看不见、可达性判错 |

### 5.6 `FanOut` 漏在调用图之外

裁剪不可达函数时只跟 `ir.Call` / `ir.TailCall`，**看不见 `ir.FanOut`**。
结果：入口存在，却去调用一个已被丢弃的函数。**每个类的生命周期处理器都被删了。**

> 教训：**新增 IR 原语时，必须同时更新所有调用图分析。**

### 5.7 入口点被重复保留

已经有 `on tick` 声明时又保留生成入口，报 `E_FN_RESERVED` 说它和自己冲突。
修法：**只保留「没有声明但会生成」的入口。**

### 5.8 其它静默失败

| 症状 | 根因 |
|---|---|
| `[wrapping]` 解析了但从不消费 | 未知属性没有拒绝机制；现在有 |
| `const BIG = 3000000000` 静默回绕成负数 | 字面量没有范围检查；现在 `E_INT_RANGE`，检查前先并入负号 |
| `fn Foo` 与 `fn foo` 撞成一个函数 | 1.12.2 归一化；现在 `E_FN_COLLISION` |
| `fn init()` 覆盖编译器生成的 init | 保留名未登记；现在 `E_FN_RESERVED` |

### 5.9 同一个周期有两个身份

周期最初按**写法**命名：`[every("5s")]` → `p.5s`、`[every("100ticks")]` → `p.100ticks`。
两个写法说的是同一件事，于是得到**两个计数器**，各自数各自的，互相漂移。
而每个单独看都正确——所以只能靠「把两个声明写在一个程序里」才发现。

修法：周期名从 **tick 数**推出（`p.100`、`every/100t`），写法只是输入。

> 教训：**凡是「用户能写出两种等价写法」的地方，内部标识必须从归一化后的值
> 推出，不能从写下的文本推出。** 时长换算本来就有这个问题，`DURATION` 词法
> 单位只是把它挪了个地方。

### 5.10 周期链在文件级计算

每个文件各自算「我驱动哪些周期」，所以两个文件都写 `[every("5s")]` 时各生成一个
`p.100` 和一个 `every/5s`，互相抢同一个计数器。单文件测试全绿。

修法：周期和 `boot` 一样是**模块级事实**，收集到 driver 再统一生成时钟。

> 教训：**一个事实如果跨文件才有意义，就不能在文件级生成。** 判断标准很简单：
> 「两个文件都写它」会不会产生两个实体？会，就是模块级的。

### 5.11 工具层面的坑（会浪费大量时间）

**编辑工具在字符串里遇到反引号会静默失败**，报 `Expected ',', got 'ident'` 之类。
**每次声称改完之后，必须用 grep / read 复查。** 这一路因此白干过好几次。

**`-out` 不清空输出目录。** 我因此报错过一次数字（132 vs 真实的 124）。
**每次测量前先 `Remove-Item -Recurse -Force <dir>`。**

## 6. 验证方法（这是这个项目的核心方法论）

### 6.1 baseline = 生成结果，不是功能列表

编译器唯一的产物就是它的输出。所以「输出变小了」和「输出的含义悄悄变了」
在一个 diff 里长得一模一样——**除非输出本身被签入并被逐字比对**。

golden 在 `internal/driver/testdata/golden/*.txt`，8 个文件（2 示例 × 4 级别）。

**重签流程（不许跳步）**：

```powershell
go test ./internal/driver -run GoldenBaseline            # 先看它红
go test ./internal/driver -run GoldenBaseline -update    # 重签
git diff internal/driver/testdata/golden                 # ★必须逐行读 diff
```

**读 diff 时看什么**：
- 有没有出现 `# files=` 行 → 说明文件数/命令数变了
- 语义是否等价（例如 `execute @s[t>=0]` → `function X unless @s[t=-1]` 等价）

### 6.2 语义测试跑在真运行时上

`internal/driver/*_test.go` 里有一批测试把编译产物喂给 `gomc.exe` 执行，
再和 Go 里独立实现的参考结果比对。**不要只信静态断言。**

### 6.3 实测数字（改完要复测）

```powershell
foreach ($lvl in 0..3) {
  Remove-Item -Recurse -Force wtest\m$lvl -EA SilentlyContinue
  go run ./cmd/ggm -q -O $lvl -out wtest\m$lvl examples\luo-math-full.ggm 2>$null
  # files / commands
}
```

| 级别 | 文件 | 命令 |
|---|---|---|
| -O0 | 16 | 129 |
| -O1 | 15 | 127 |
| -O2 | 15 | 124 |
| -O3 | 15 | 124 |

## 7. 与用户协作的方式

**这一节同样重要。** 用户的风格很明确，违反会浪费双方时间。

### 7.1 硬性要求

| 要求 | 出处 |
|---|---|
| **先数、再设计** | 「你得先探索真优质项目再决定语法抽象」 |
| **不要给还没写过的项目设计语法** | 规范 v1.0 的设计原则 |
| **不要扫描外部 `.mcfunction`** | 「本项目还是少做 mcfunction native 的扫描功能」。检查只针对 GGM 自己的程序 |
| **注释默认关闭** | 「注释可选生成，默认关闭」，用 `-comments` 打开 |
| **不要加 Node 依赖** | 「node 太重了」，选定 Go |
| **先 git** | 改完就提交 |
| **先加硬上限再查 bug** | 「先加memory上限再查」 |

### 7.2 用户会做什么

- **直接推翻我的结论**，而且通常是对的。例如：
  - 我以为数据表不值得做（只数出手写 2 处）→ 用户：「数据包需要！！！！」
  - 我建议补生成器 → 用户：「不应该补生成器」
  - 我把扩展名写成 `.ggm` 之前的 `.cmcf` → 用户直接给新名
- **看得出偷懒和含糊**。用词要精确，「大概」「应该」会被追问。
- **中文交流，要简洁**。不要复述已经说过的东西。

### 7.3 什么样的回答是对的

**给证据，不给断言。** 这一路最有效的模式是：

1. 说结论
2. 附**可复现的命令与实测输出**
3. 主动说**自己哪里错了**（用户会因此更信任其余部分）

反例：我在「改目录名」时去查 go/gopls 进程，方向完全错了——
真正的原因是**我自己的程序进程**把工作目录锁住了。这类错误要主动承认。

### 10.1 加新语法之前的检查清单

1. 读 `docs/roadmap.md` —— 这个特性是不是被砍过？复活条件满足了吗？
2. 在参考项目里**数**真实用例（不是「有用」，是「不用活不下去」）
3. 改 `docs/GGM-语法规范-v1.0.md` **先于**改代码
4. 加诊断码，并写进规范的检查清单表
5. 改完跑 golden，**读 diff**，再决定重签
6. 升版本号（含义变了 → 次版本）
7. 提交 + 打 tag
