# Roadmap —— 被砍掉的语法

规则：**每一条都要等到出现第 3 个真实用例再实现。** 不是「有用就做」，而是「不用就活不下去才做」。

| 特性 | 为什么砍 | 复活条件 | 替代 |
|---|---|---|---|
| `task` / `wait` / `enter` / `spawn` | `class + @tick` 已经覆盖跨 tick，且更贴近知识库「状态挂在实体上」 | 出现「一段线性时序代码」写三遍以上 | `class CastTimer { @tick fn tick() }` |
| `pure` 关键字 | 纯度应靠推断，不该让用户写 | 需要 `comptime` 调用用户函数 | 无命令即纯，自动判定 |
| `enum` / `match` | `luo/math` 零使用 | 状态数 > 8 且要穷尽检查 | `if/else` |
| `fixed<N>` / `within` | `luo/math` 全是 `int` | 出现小数算术错误导致的线上 bug | 千分比 `int` |
| `ref<T>` / `list<T,N>` | 跨实体引用 = O(N) 广播，本来就该显式 | 有明确的一对一引用需求 | 消息队列 / 显式广播写 |
| 泛型 + trait 约束 | `max<int>` 在 stdlib 写死就够 | stdlib 出现第三个同构函数 | 内置 `min/max/abs/clamp` |
| `pool_*` 实体池 | 用 `for e in entities<>` 手写 3 行 | `ini_sum` 这种模式出现 3 次 | 手写 |
| `#[inline]` | 无真实用例 | 递归需要编译期展开 | 无 |
| `#[nbt_bits]` 位编码 | 只在 `on spawn` 用一次 | 需要把多值状态压进可运算整数 | 手写 `scoreboard players add ... {NBT}` |
| `@broadcast` 方法 | 广播写语句已覆盖 | 需要跨类广播 | 广播写语句 |
| `goto` / `break` / `continue` | 自递归够用 | 出现无法用自递归表达的跳出 | 标志位 |
| `every ... phase N` 手动相位 | 编译器自动分配 | 需要手工错开重任务 | 自动 |
| 规则引擎 `rule when then` | 分阶段求值成本高 | 规则数 > 30 | `on tick` + `if` |
| 声明式 `derived` / 脏标记 | 调试成本大于收益 | 出现「忘了更新缓存」的线上 bug | 手写脏标记 |
| LSP / Playground | 20 个用户 | 用户数 > 50 | 无 |

## 已实现但有已知缺口的

这些不是被砍的特性，是**已经进入语言、但还没兑现全部承诺**的地方。
它们比上面的清单更危险，因为用户可以合法地写出它们。

| 项 | 现状 | 缺口 | 补上的前提 |
|---|---|---|---|
| `#[wrapping]` | 解析、校验、接受 | 不产生任何效果——因为 `W_WRAP_UNPROVEN` 还没实现，没有警告可关 | 逐表达式的区间分析。没有参数范围注解时，任何含变量的 `+` 都会报警，所以要先有范围来源 |
| `-O3` | 与 `-O2` 相同 | 没有属于 O3 的 pass。原本留着 `rotateLoops` / `rotatePostTest` 做真正的循环旋转，但它们**已被删除**——`while` 现在按 `if cond { loop cond { body } }` 在 AST 层等价改写，那才是正确且不需要证明的做法 | 出现只有跨块值分析才能证明的改写 |
| 字面量范围 | 已强制 `E_INT_RANGE` | 只覆盖字面量；`2147483647 + 1` 这种含变量的表达式仍然静默回绕 | 同 `#[wrapping]` 的区间分析 |
| `none` | 词法上存在（`token.go` 映射到 `FALSE`） | 规范里 `ref<T>` 的 `none = -1` 语义没实现，而 `ref<T>` 本身在砍掉清单里 | `ref<T>` 复活时一起处理 |

**共同根源**：三条都卡在同一件事上——**值域分析**。
它不是优化，是**证明能力**：`#[wrapping]` 需要它来知道该不该警告，
溢出检查需要它来知道字面量之外还有哪些值越界。

`-O3` 已经不在这个分组里了：它当初的缺口是「循环旋转需要值编号」，
但那个结论是**错的**——循环不需要旋转，只需要换一种等价写法。

### 另一个还没做的证明能力

跨函数复用 objective 需要的是**过程间活跃范围**，不是值域。

现在名字在模块内唯一（见 `OPTIMIZATION.md` 第 7 节），代价是 objective 偏多：
一个只在某函数内短暂存活的名字，也必须和全模块所有名字区分开。
放宽到「分配器能证明不会同时存活就能复用」可以显著减少 objective 数，
但那只在**收益足够大**时才值得做——1.12.2 的每个 objective 只在加载时花一条命令。

**当前判断：先不做。** 等出现真正撞上 16 字符上限、或 objective 数量成为实测瓶颈时再说。
